# Skill：skill-code-review（变更自审/互审）

> **版本**：v0.2
> **变更记录**：v0.1 初稿（2026-08-15）→ v0.2 生长（2026-08-15，用户指令）：新增首帧可玩性、生命周期耦合、冒烟测试三个维度（两条实战教训 + 决策 #25）

## 触发条件

提交前自检、reviewer 代理审查、任何"改完请检查"的要求。

## 审查维度（对照规范）

1. **依赖方向**：对照 `docs/architecture/README.md` §3 白名单；违规 import = 阻断
2. **类型**：无 any 逃逸、无 `@ts-ignore`；严格模式通过
3. **游戏生命周期**：销毁时 rAF/interval/超时/事件/音视频全部清理
4. **设计合规**：色值/纹理/组件/动效对照 design-language.md（走 skill-design-system 清单）
5. **双语**：对照 skill-i18n 清单
6. **明暗**：`html.dark` 下可用
7. **无障碍**：焦点可见、键盘可达、弹窗 aria/焦点陷阱/ESC（design-language.md §12、§15）
8. **性能**：游戏组件懒加载；无不必要的全局监听
9. **验证**：typecheck + build 通过；若有 `engine.test.ts` 冒烟测试，需 node 直跑通过
10. **提交规范**：中文、Conventional Commits、拆分合理
11. **首帧可玩性**：游戏启动/重开后首帧即有可玩内容（首块/首目标生成，曾漏 spawn 导致空棋盘）
12. **生命周期耦合**：计分/阶段通知等高频回调不得触发壳层 effect 重建（曾因 effect 依赖 score 而在每次得分时销毁游戏实例）；涉及壳层接口变更需 ADR
13. **阶段状态机**（ADR-0007）：mount 后须上报一次初始阶段；menu/over 阶段不得响应玩法输入

## 输出格式（审查报告）

- 结论：通过 / 有条件通过 / 不通过
- 问题分级：
  - 🔴 阻断：违反红线/依赖规则/验证不通过
  - 🟡 建议：质量问题，不阻塞
- **每条问题必须给出规范出处**（文件 + 章节）；无法判断的标「待确认」，不得臆断

## 红线

- 结论必须有出处；凭感觉下结论 = 幻觉，禁止
- 不直接改代码（审查与修改分离）
