# Skill：skill-i18n（双语文案）

> **版本**：v0.1
> **变更记录**：v0.1 初稿（2026-08-15）

## 触发条件

新增/修改任何用户可见文案（公共 UI、游戏元数据、提示信息）。

## 规则

1. **键名**：camelCase，按域分组（`common.*` / `lobby.*` / `shell.*` / `gameWindow.*`）；键名描述语义而非位置
2. **zh 与 en 同步**：两个语言文件必须同时修改；只写一个语言 = 阻断级问题
3. **游戏双语**：游戏自身的 name/description/说明写在 manifest（`{ zh, en }`）；游戏内文案建议同样双语策略
4. **禁止硬编码**：公共界面不得出现裸字符串（游戏画面内由游戏自管的文案除外，但需在 manifest 注明语言策略）
5. **文案膨胀**：按钮/卡片标题按中文最长情形验收，不依赖英文宽度
6. **数字/日期**：不硬编码格式；分数用西文数字 + tabular-nums
7. **语气**：标题沿用规范排版（英文全大写 + 斜体；中文字重替代——见 design-language.md §3.3/§3.4）

## 检查清单

- [ ] zh/en 两份都存在且语义一致
- [ ] 无硬编码公共文案
- [ ] 切换语言后 UI 无溢出/截断
- [ ] 标题排版符合 §3.3/§3.4

## 红线

- 单语言提交
- 机器翻译后不人工校对（机翻腔文案不得进入仓库）
