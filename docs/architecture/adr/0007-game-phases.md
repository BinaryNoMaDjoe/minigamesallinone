# ADR-0007：游戏阶段状态机（menu/playing/paused/over）与壳层控制条适配

- **状态**：accepted
- **日期**：2026-08-15

## 背景

用户要求俄罗斯方块与后续游戏"做完整"：具备开始游戏、暂停、结束游戏、返回主菜单等内容（参照原版）。壳层控制条（暂停/重开按钮）此前只通过 `GameInstance.pause/resume/restart` 单向调用游戏，**无法感知游戏内部处于哪个阶段**（如游戏停在主菜单时，壳层仍显示暂停按钮，语义混乱）。

## 决策

- 游戏契约新增**阶段状态机**：`GamePhase = 'menu' | 'playing' | 'paused' | 'over'`（decision #24）
- `GameCallbacks` 新增**可选** `onPhase?(phase)`：游戏阶段变化时通知壳层；未实现的游戏视为常驻 `playing`（向后兼容）
- 壳层控制条随阶段适配：
  - `menu`：隐藏暂停与重开（游戏主菜单自带"开始游戏"）
  - `playing` / `paused`：显示暂停/继续按钮（图标随阶段切换）
  - `over`：隐藏暂停，保留重开（"再来一局"）
- 游戏在 `mount` 后主动上报一次当前阶段（初始同步，避免壳层默认值与游戏实际阶段不一致）

## 理由

- 用户明确指令（"增加开始游戏、返回主菜单、结束游戏，做完整"）
- 可选回调保持既有游戏（未实现 onPhase 者）行为不变
- 游戏内部阶段语义归游戏所有，壳层只做展示适配，边界清晰

## 后果

- 约束：`pause/resume/restart` 语义仍由游戏解释（如 menu 阶段收到 pause 应忽略）
- 约束：新增游戏若实现阶段机，必须 mount 后上报一次初始阶段（写入 skill-add-game）
