# ADR-0001：游戏注册表模式（Registry Pattern）

- **状态**：accepted
- **日期**：2026-08-15

## 背景

项目将收录"多个（甚至很多个）小游戏"，且用户明确表示游戏清单将逐步确定。若每加一个游戏都要改大厅、路由、列表等公共代码，游戏数量上来后维护成本与出错率将失控。

## 决策

- 每个游戏 = 独立目录 `src/games/<game-id>/`，内含 `manifest.ts`（元数据 + 双语 + 主题 + 画布比例）与 `Game.tsx`（游戏本体）
- `registry.ts` 通过 `import.meta.glob` **自动汇总**所有 manifest，禁止人工维护
- 大厅卡片墙、弹窗入口全部由注册表驱动；游戏组件经 `React.lazy` 按需加载
- 新增游戏 = 只新增一个目录，不改任何现有文件

## 理由

- 加游戏只写游戏本身，成本恒定（用户需求：游戏清单慢慢说，架子必须游戏零感知）
- 懒加载保证首屏性能不随游戏数量增长而劣化
- manifest 是唯一契约，壳层只认识它，不认识具体游戏

## 后果

- 正面：游戏零耦合、可独立回滚、并行开发互不干扰
- 约束：manifest 字段变更需同步全部游戏目录；游戏间禁止互相 import（由架构分层规则强制）
