# ADR-0005：本地存储 + ScoreService 抽象

- **状态**：accepted
- **日期**：2026-08-15

## 背景

用户明确：先做纯本地版本（轻后端），后续可接入正式域名与成熟后端经验。数据层需要现在就把"换后端"的成本压到最低。

## 决策

- 所有持久化（最高分、最近游玩、收藏、设置）经 `ScoreService` 接口写入；首版实现为 localStorage
- 游戏只调用接口上报统一结构 `{ 游戏id, 分数, 耗时, 日期 }`，**禁止**游戏直写 localStorage
- 未来接后端 = 新增 HTTP 实现替换 localStorage 实现，游戏代码零改动

## 理由

- 用户指令：先纯本地、轻后端（process/README.md 决策记录，用户原话"先做纯本地版本，轻后端，我有正式域名可以接入"）
- 接口前置使"换存储"成为配置级变更而非全库改造

## 后果

- 约束：接口一经稳定不轻易变更；变更需新 ADR
- 约束：本地数据无跨设备同步（首版接受的代价）
