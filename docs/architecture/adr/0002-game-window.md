# ADR-0002：游戏弹窗运行模式（GameWindow）

- **状态**：accepted
- **日期**：2026-08-15

## 背景

用户明确倾向：游戏在网页中**弹窗运行**——窗外和窗框表现遵循网页级规范，窗内是实际游戏区域、遵循游戏级规范。此前默认方案（独立全屏路由页）被此决策取代。

## 决策

- 游戏不在独立路由全屏运行，而在大厅之上以弹窗运行，同一时间只允许一个游戏窗口
- 实现为公共组件 `GameWindow`（`src/components/ui/`），规格遵循 design-language.md §15
- 分区规则：
  - **窗外**（遮罩层 + 背后大厅）= 网页级规范
  - **窗框**（容器、标题栏、控制条、关闭钮、边框阴影）= 网页级规范
  - **窗内**（游戏画布区域）= 游戏级规范，游戏自由发挥
- 壳层提供：标题栏（游戏名双语）、分数/最高分、暂停、重新开始、关闭、玩法说明气泡

## 理由

- 用户明确指令（2026-08-15 会话确认，见 process/README.md 决策记录 #5）
- 大厅始终保持上下文，游戏与网页气质统一，且天然支持"玩完回大厅"的浏览模式

## 后果

- 正面：游戏只需实现画布内容与状态接口，暂停/计分/关闭等重复劳动由壳层承担
- 约束：无独立游戏路由页；窗内与窗外视觉规范的边界必须严格执行（design-language.md §15）
- 约束：弹窗需满足焦点陷阱、ESC 关闭、背景滚动锁定等无障碍要求
