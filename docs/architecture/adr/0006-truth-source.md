# ADR-0006：文档即真相源与规范生长机制

- **状态**：accepted
- **日期**：2026-08-15

## 背景

用户明确要求：项目要**杜绝幻觉和意淫**，且在必要阶段**已有的规范流程需要生长或迭代**。这需要把反幻觉与规范迭代变成仓库的元规则，而不是依赖某个会话的记忆。

## 决策

- **文档即真相源**：一切事实以 `docs/` 为准；事实链：仓库文档 > 用户明确指令 > 明确标注的推断；代码与文档冲突时以文档为准回查
- **AGENTS.md** 作为所有 AI 会话的第一入口与硬性红线（红线第一条即反幻觉）
- **规范生长机制**（docs/process/evolution.md）：五步流程（提案→确认→落档→实施→回查）、ADR 生命周期（proposed→accepted→superseded）、版本号与变更记录规则
- 决策记录唯一主表：docs/process/README.md §8；其他文档中的决策表为其子集快照
- 所有规范文档文首带版本号 + 变更记录

## 理由

- 用户明确指令（process/README.md 决策记录 #14）
- 靠文件而非靠记忆：任何 AI 会话、并行子代理进入仓库后行为可对齐
- 生长示例已验证：暗色主题由亮色规范生长而来，来源列可追溯（design-language.md §2.5）

## 后果

- 正面：可追溯、可回退、可审计；"两张皮"与幻觉有制度性拦截
- 约束：文档修改有流程成本；宪法级文档必须用户确认
